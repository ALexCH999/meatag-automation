# Суточные продажи по артикулам

Скрипт читает выгрузку заказов `sales.csv` и для каждого артикула и дня считает два показателя:

- `orders` — число заказов, включая отменённые;
- `revenue` — выручка: сумма `quantity × price` только по заказам со статусом `delivered`.

Результат сохраняется в `daily_by_sku.csv` с колонками `sku, order_date, orders, revenue`. Строки отсортированы по артикулу, затем по дате. Каждый `order_id` учитывается один раз.

## Как запустить

Нужен Python 3. Основной скрипт работает без внешних библиотек. Pandas нужен только для проверки результата.

1. Положите `sales.csv` в папку рядом с `process_sales.py`.
2. Из этой папки выполните:

   ```bash
   python3 process_sales.py
   ```

   На Windows может понадобиться `python` вместо `python3`.
3. Результат появится в этой же папке в файле `daily_by_sku.csv`. Если файл уже есть, он будет перезаписан. В консоль скрипт выводит итоги: число строк, дублей, уникальных заказов и общую выручку.

Чтобы проверить результат:

```bash
python3 -m pip install -r requirements.txt
python3 check.py
```

## Как проверял, что расчёт верный

Для проверки есть отдельный скрипт `check.py`. Он пересчитывает всё заново другим способом: через pandas, а не через `csv` и словарь, как в основном скрипте. Затем он сравнивает свой результат с `daily_by_sku.csv`: заголовки, каждую строку, порядок сортировки и контрольные суммы. Если что-то не совпало, скрипт сообщает номер первой отличающейся строки.

На выгрузке, с которой я работал, проверка проходит: `OK: 631 строк, уникальных заказов = 13798, orders = 13798, revenue = 10276540`.

Контрольные цифры:

- в выгрузке 13 858 строк, из них 60 повторов, остаётся 13 798 уникальных заказов;
- сумма `orders` в результате равна 13 798, то есть ни один заказ не потерялся и не посчитался дважды;
- после нормализации статусов получается 12 047 заказов `delivered` и 1 751 `cancelled`, вместе снова 13 798;
- общая выручка 10 276 540 рублей одинакова в основном скрипте и в проверке;
- все 631 пары «артикул — день» совпадают построчно.

Дополнительно проверено, что у каждого артикула в выгрузке одна цена, а повторы `order_id` являются полными копиями исходных строк.

## Какие проблемы нашёл в данных и как с ними поступил

- **Дубли.** 60 строк повторяют уже встречавшийся `order_id`. Все они полностью совпадают с оригиналами, конфликтующих повторов нет. Учитывается первое вхождение, остальные пропускаются.
- **Разный регистр в статусах.** Встречаются `Delivered`, `DELIVERED`, `Cancelled`, `CANCELLED`. Привожу статусы к нижнему регистру.
- **Опечатка `canceled`** (с одной «l») вместо `cancelled`. Заменяю на `cancelled`.
- **Пробел в конце статуса.** В 11 строках статус записан как `delivered `. Убираю через `strip`, на результат это не влияет.
- **Пустое `quantity`.** Оно пустое у четырёх отменённых заказов. Они остаются в `orders`, а выручка по ним не считается, поэтому пропуск ни на что не влияет.

## Что не доделано и в чём не уверен

- Результат я сам вручную не пересчитывал, а опирался на `check.py` и на проверку через Claude.
- `check.py` написан иначе, чем основной скрипт, но правила в нём те же: дубль определяется по `order_id`, статусы нормализуются так же. Он ловит ошибки реализации, но не покажет, если я неверно понял условие. При пустом `quantity` у заказа `delivered` он считает 0, а основной скрипт в этом случае упадёт.
- Если один `order_id` встретится дважды с разными данными, скрипт оставит первое вхождение и ничего не сообщит. В этой выгрузке таких случаев нет.
- Скрипт рассчитан на числовые `quantity` и `price` у заказов `delivered`. Пустое значение или текст приведут к ошибке. В этой выгрузке такого нет.
- Статусы, отличные от `delivered` и `cancelled`, скрипт не выделяет: такой заказ попадёт в `orders`, но не в выручку. В выгрузке таких нет.
- Если `sales.csv` не найден, скрипт пишет сообщение, но завершается без кода ошибки.
